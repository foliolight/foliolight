# Test Strategy

Status: Draft v0.1.

## 1. Principles

- **No real or sensitive data, ever.** All fixtures are synthetic, generated by a script, and checked automatically.
- Hostile inputs are first-class test cases, not an afterthought.
- Every bug fix adds a regression fixture.
- Tests run on Windows in CI, because Windows is the primary platform and path handling is Windows-specific.

## 2. Test layers

| Layer | Tooling (candidates, confirmed in Phase 0) | Scope |
| --- | --- | --- |
| Unit | `cargo test` | Parsers, FPath, detection, mapping rules, version strategies, anchors, fingerprints, launcher validation, config and policy precedence |
| Property-based | `proptest` | Parser round trips, FPath evaluation invariants, canonicalization stability, path validation (generated hostile paths) |
| Fuzzing | `cargo-fuzz` (libFuzzer) | One target per parser, FPath parser, schema and pack validators, sidecar loader. Short runs on every pull request, longer nightly runs; corpus committed. OSS-Fuzz application after 1.0 if accepted. |
| CLI golden tests | Snapshot tests on `--json` output | Every command and exit code |
| UI component | Vitest and Testing Library, with axe-core | Components and states, including empty, loading, error, read-only |
| End-to-end | WebdriverIO with `tauri-driver` on Windows | Core user journeys on the built app |
| Accessibility | axe-core in component and end-to-end tests; manual scripts with Narrator, NVDA, JAWS | See [ui spec](../specs/ui.md#testing-and-reporting) |
| Performance | `criterion` benchmarks for the core; end-to-end timing scripts | Budgets in Section 6 |
| Network silence | Run the app with updates disabled under a network monitor (for example, a Windows Filtering Platform audit or a loopback-only firewall rule) | Asserts zero outbound connections |
| Environment matrix | Manual and scripted runs on VMs | Section 7 |

## 3. Synthetic sample library

Generated by `fixtures/generator/` (Python, dev-only, never shipped). Deterministic: a fixed seed produces byte-identical output, so diffs in pull requests are meaningful.

### Fictional CSPs

| CSP | Layout | Formats | What it exercises |
| --- | --- | --- | --- |
| **Aster Example Cloud** | Standard convention (`SSP`, `SAP`, `SAR`, `POAM`, `Other`) | OSCAL JSON | The happy path; two SSP versions with controlled differences; back-matter with base64 PNG and SVG; relative links to a PDF and a DOCX placeholder |
| **Brightwater Example Hosting** | Nonstandard: `01 - System Security Plan`, `Assessment/2026-Q1/Results`, `POA and M`, `Misc 2` (unmapped) | OSCAL XML | Mapping rules, unmapped folders, XML namespaces, filename-pattern versioning (`ssp_v3.xml`, `ssp_v4.xml`) |
| **Cobalt Example Systems** | Deep nesting (6 levels), 2,000 small files across monthly folders, mixed file types | OSCAL YAML, generic JSON, generic XML, CSV, PNG | Lazy listing, large folders, version groups with "estimated" ordering, comment drift across three POA&M versions (items added, removed, reworded, UUIDs regenerated in one version) |

Cobalt Example Systems also includes a `VulnReports` folder with three monthly synthetic vulnerability reports (JSON), each with about 1,000 findings spread across dispositions (open, accepted, false positive, fixed), reachability and exploitability flags, impact ratings, and due dates. A generated large variant has 200,000 findings. The generator also writes the **expected counts** for every chart in the example dashboard pack, so tests can check that Foliolight's numbers match exactly.

**Program JSON artifacts** ([issue #2](https://github.com/foliolight/foliolight/issues/2)): Aster Example Cloud also includes an `Other` file that is plain JSON (not OSCAL) whose `$schema` value is the identifier of a published program schema for a machine-readable submission artifact. The identifier is only compared as text and never fetched. The content is synthetic. Tests check that detection reads `$schema`, that the example pack `example-publisher.program-json-artifacts` is suggested, and that the structure check runs against the schema copy shipped in that pack.

**Bundled FedRAMP schemas:** synthetic documents are generated from each bundled published schema (valid, missing a required field, wrong enum value, extra field, and a `$schema` version newer than bundled), plus a document with no `$schema`. Tests cover detection, version choice, the "newer than this copy" message, dashboard counts for the three vulnerability-related schemas against an independent script, and turning the bundled pack off. CI verifies every bundled file's hash against `PROVENANCE.yaml`. See [bundled-program-schemas](../specs/bundled-program-schemas.md#11-testing).

**CSV vulnerability reports:** Brightwater Example Hosting delivers the same kind of vulnerability report as CSV instead of JSON: semicolon-delimited, two title lines above the header row, `MM/DD/YYYY` dates, and `Yes`/`No` flags. The generator writes a CSV version of one Cobalt JSON report as well, and tests check that the CSV view (which extends the JSON dashboard view) produces **identical counts** for every chart and tile.

**Open-check fixtures** ([issue #6](https://github.com/foliolight/foliolight/issues/6)): the fourth monthly vulnerability report adds two new fields and drops one expected field ("fits, with differences"); a misfiled SSP sits inside `VulnReports` ("does not fit"); and a truncated report ends mid-record ("cannot read").

**Version ordering fixtures** ([issue #5](https://github.com/foliolight/foliolight/issues/5)): Aster's SSP folder has files whose modified times are deliberately in the wrong order compared with `metadata/last-modified`, plus one file with no in-document date, to test `auto` ordering, the disagreement note, and the "estimated" marker.

**Hash list fixture** ([issue #4](https://github.com/foliolight/foliolight/issues/4)): Aster's SSP folder includes a `SHA256SUMS` file with one correct entry, one wrong entry, and one entry for a missing file.

Each CSP includes all six OSCAL model families where it makes sense (SSP, SAP, SAR, POA&M, and at least one catalog, profile, and component definition shared under `Other`).

### Data rules

- Names: obviously fictional, containing "Example."
- Domains: `example.com`, `example.org`, `example.net` only (reserved by RFC 2606).
- IP addresses: documentation ranges only (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `2001:db8::/32`).
- People: generated names from a fixed fictional list; emails at example domains.
- Control content: generic paraphrased text written for the fixtures, not copied from real packages.
- A CI check scans every fixture for email addresses, IPs, domains, and phone numbers outside the allowed ranges and fails the build if any are found.

### Sizes

- Small library (under 20 MB total) is committed under `fixtures/library/`.
- Large files are **generated at test time**, not committed: 100 MB OSCAL JSON SSP, 300 MB OSCAL XML assessment results, 500 MB generic JSON array, 60 MB YAML.

### Example schema packs

- `packs/examples/example-publisher.oscal-ssp-compact`: signed with a test key.
- `packs/examples/example-publisher.vuln-report-dashboard`: dashboard pages for the synthetic vulnerability reports.
- `packs/examples/example-publisher.program-json-artifacts`: views matched by `$schema` for non-OSCAL program JSON artifacts, with a copy of the published schema for the structure check.
- A tampered copy (one byte changed), an unsigned copy, and a copy containing a forbidden file type, used for negative tests.

## 4. Hostile-input corpus

Committed under `fixtures/malicious/`, each with an expected outcome (reject with a specific error code, or render safely).

| Case | Expected outcome |
| --- | --- |
| XML with `DOCTYPE` and external entity (`SYSTEM "file:///C:/Windows/win.ini"`) | Rejected: DTD not supported |
| XML "billion laughs" | Rejected: DTD not supported |
| XML with external entity pointing to a UNC path | Rejected; no SMB connection attempted |
| JSON and XML nested 100,000 levels | Rejected: depth limit; no stack overflow |
| YAML alias bomb | Rejected: aliases not supported |
| YAML with custom tags (`!!python/object`) | Tag ignored, value shown as string |
| YAML with `no`, `on`, `0x1F` scalars | Shown as YAML 1.2 core schema values (`no` stays a string) |
| JSON with duplicate keys | Last value shown, warning with both locations |
| 600 MB file | Refused with size limit message |
| 70 MB single string | Refused or truncated with a clear message |
| Invalid UTF-8 and mixed encodings | Rendered with replacement characters and a warning |
| Markdown with `<script>`, `<img onerror>`, `javascript:` links | Rendered as inert text |
| Markdown with remote image | Placeholder showing URL; no request made |
| SVG with embedded script and external references | Rendered through image element; no script, no request |
| Base64 attachment claiming `image/png` but containing an executable | Not rendered; flagged as mismatched type |
| Polyglot image files | Rendered only as image; no other handling |
| Links: `..\..\..\Windows\System32\calc.exe`, `\\attacker.example\share\x.pdf`, `file://attacker.example/x`, `C:\Windows\notepad.exe`, `CON`, `file.txt:secret`, `report.pdf.` (trailing dot), `report.pdf.exe` | All blocked with specific reasons; no SMB connection attempted |
| Symlink and junction loops and links outside the root | Not followed; marked in listing |
| Sidecar with malformed YAML, huge comment text, aliases | Rejected or skipped entries with warnings; app keeps working |
| Pack with `.exe`, `.js`, `.html`, symlink, hidden file, `..` path | Rejected |
| Mapping rule with pathological regex | Linear-time matching; pattern length limit enforced |
| CSV export injection (`=HYPERLINK(...)`, `+cmd`, `@SUM`) | Prefixed with a quote in export |
| CSV input with formula cells (`=cmd|' /C calc'!A0`, `=HYPERLINK(...)`) | Shown as text; nothing evaluated or launched |
| CSV input with 100,000 columns, a 50 MB single cell, unbalanced quotes, mixed delimiters, NUL bytes | Rejected or flagged per limits with a clear message; no hang |
| Export file name suggestions from source names containing `<>:"/\|?*`, control characters, trailing dots, `CON`, `aux.json`, and 300-character names | Valid Windows names, under the length limits, readable document type and page kept |
| XLSX export of the same values | Written as text cells; no formulas in the output package (checked by unzipping and scanning the sheet XML) |
| Table rows with base64 images and attachments, exported | Cells read `[image omitted]` or `[attachment omitted: name]`; no base64 in the output |
| Structure-check schema with remote and `file:` `$ref` values | Not followed; check reported as partial; no network or file access |
| Cross-document link identifiers containing `..\`, UNC paths, or another CSP's name | Treated as plain identifiers; no path built from them; nothing outside the CSP opened |
| Pasted hash with extra text, wrong length, or MD5 length | Clear "doesn't look like a hash" or "too weak" message; never a false Match |
| Archive cases (Phase 7): zip bomb, nested zip, `..` entries, absolute paths, huge entry counts | Rejected per limits |

## 5. Key user journeys (end-to-end)

1. First run: choose library, see CSPs and document types within the listing budget, no network activity.
2. Open current SSP in Document view; filter controls by status; jump to a UUID link; view an inline diagram.
3. Open a linked PDF: confirmation, launch in default app; attempt a blocked link: clear explanation.
4. Open a 300 MB XML file: progress, browse while indexing, cancel, reopen.
5. Add comments on the July SSP; drop in the October SSP; see Attached, Changed, and Orphaned states; re-anchor an orphan; export to CSV.
6. Read-only share: commenting disabled with explanation.
7. Build a view schema from a generic JSON sample; save; reopen file with new view.
8. Install a signed pack; reject tampered and unsigned packs per policy.
9. Update check: up to date, update available, offline, blocked by proxy, disabled by policy. Download and verify success and tampered download failure (using a local test server in CI).
10. Keyboard-only and screen reader run through journeys 1, 2, 5, 11, and 12.
11. Open a new kind of file: accept the suggested view for the folder; open the next file with new fields and add them through the notice; open a misfiled file and reassign it to another document type without anything moving on disk; open a truncated file and see the plain-language error.
12. Check the hash of the open file: paste a matching hash, a wrong one, and an MD5; see the folder's `SHA256SUMS` result.
13. Filter the vulnerability dashboard to open IRV+LEV findings, export to XLSX and CSV, and confirm the rows, columns, and info sheet match the screen. The Save As dialog opens in Downloads with the suggested name, and choosing a library folder asks for confirmation.
14. Follow a POA&M item's control link to the current SSP, and a link whose control is missing.
15. Open Brightwater's CSV vulnerability report: it opens as a table with no view; accept the suggested CSV view; see the same dashboard as the JSON reports, with the same counts as the CSV fixture's expected values.

## 6. Performance budgets

Measured on a reference machine (to be defined in Phase 0; ASSUMPTION A-24: a 4-core laptop with 8 GB RAM and SSD, typical of agency-issued hardware). Values are targets to validate in the Phase 0 spike.

| Measure | Budget |
| --- | --- |
| Cold start to interactive window | Under 1.5 seconds |
| Idle memory (all processes including WebView2) | Under 200 MB |
| List a library of 10,000 files on local SSD | First results under 0.5 seconds; complete under 2 seconds |
| List a folder of 1,000 files on SMB over a typical office network | First results under 1 second |
| Open a 10 MB OSCAL JSON SSP to first Document view | Under 1 second |
| Open a 100 MB JSON to first page of Outline view | Under 3 seconds |
| Open a 300 MB XML to first page of Outline view | Under 5 seconds (indexing continues in background) |
| Memory while viewing a 300 MB file | Under 600 MB total |
| Scroll a 10,000-row table | No visible jank (60 frames per second target) |
| Build datasets for a 200,000-record vulnerability report during the first pass | Adds under 20 percent to open time |
| Recompute every chart on a dashboard after a filter change (200,000 records) | Under 100 ms |
| Switch back to a recently opened document (session still cached) | Under 200 ms |
| Quick fit check when opening a file in a folder with a view | Under 200 ms (sampled; large files refine after indexing) |
| Read in-document dates for a folder of 50 versions on local SSD | Under 300 ms |
| SHA-256 of a 100 MB file, computed during indexing | Adds under 10 percent to open time |
| Export 200,000 filtered rows to CSV or XLSX | Under 5 seconds; constant memory |
| Release zip size (standard build) | Under 15 MB |

Regressions over 10 percent fail the nightly performance job.

## 7. Environment matrix

| Environment | Why |
| --- | --- |
| Windows 10 22H2 x64 | Long-tail agency images |
| Windows 11 (current release) x64 and ARM64 | Primary target |
| Windows Server 2019 and 2022 with fixed-version WebView2 build | Jump boxes and VDI |
| Standard user (no admin) | Default agency posture |
| AppLocker default rules enabled | Confirm documented behavior and allowlisting guidance |
| WDAC or Smart App Control | Signing behavior |
| Library on SMB share (read-write and read-only) | Performance, refresh, comments disabled state |
| OneDrive library with cloud-only placeholders | Placeholder detection and warnings |
| High contrast theme, 200 and 400 percent zoom, Narrator, NVDA, JAWS | Accessibility |
| FIPS policy enabled | Update check over Schannel still works |
| No network, captive network, TLS-inspecting proxy | Update check failure modes |

## 8. Definition of done for any feature

- Unit tests and, where it parses input, fuzz target and hostile fixtures.
- Accessibility: keyboard operable, axe-core clean, screen reader labels reviewed.
- Docs updated (spec and user help).
- No new network access, no new writes outside the documented locations.
- License scan clean for any new dependency.
